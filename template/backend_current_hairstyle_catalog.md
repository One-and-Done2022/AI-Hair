# 后端当前生效发型清单

更新时间：2026-03-31

这份清单以当前后端真实生效数据为准，来源于：

- `backend/app/data/faceprompt/hairstyles_male.json`
- `backend/app/data/faceprompt/hairstyles_female.json`

说明：

- 当前后端没有单独维护刘海分类
- 当前后端是“完整发型模板”模式，不是“主发型 + 刘海标签”拆分模式
- 前端和接口实际拿到的是完整发型条目，以及它对应的 `gender`、`category_key`、`category_label`、`style_line`、`tags`

## 一、当前总数

- 男生发型：23 类
- 女生发型：33 类
- 合计：56 类

## 二、当前分类方法

后端当前使用三层信息组织发型：

### 1. 性别层

- `male`
- `female`

这是第一层主分组。

### 2. 主分类层

这是当前最核心的分类方式，使用：

- `categoryKey`
- `categoryLabel`

前端如果做发型分类筛选，应该优先使用这一层。

### 3. 风格线层

每个发型还带：

- `styleLine`

当前可见的风格线主要是：

- `realistic_editorial`
- `fashion_editorial`

这一层更适合做辅助筛选或排序，不建议替代主分类。

### 4. 标签层

每个发型还有：

- `detailTags`

这层适合做搜索词、辅助筛选和推荐，不是独立发型分类体系。

## 五、后端当前没有的内容

以下内容目前不是后端正式结构的一部分：

- 单独的刘海分类表
- “主发型 + 刘海标签”的组合系统
- 独立 bangs / fringe taxonomy

这意味着当前系统里：

- 刘海通常被包含在某个完整发型的 `promptCore` 或 `detailTags` 里
- 前端如果只按后端现状接入，不适合单独做刘海筛选

## 六、给前端的实际使用建议

如果你现在只按后端真实数据接前端，建议这样用：

### 一级筛选

- 男生
- 女生

### 二级筛选

男生：

- 清爽短发
- 韩系修饰
- 纹理烫发
- 造型感

女生：

- 短发利落
- 层次中长发
- 长发气质
- 氛围卷发

### 辅助筛选

- `styleLine`
- `detailTags`

不要在当前版本里单独做“刘海筛选”，因为后端还没有把刘海拆成正式分类维度。

## 七、当前结论

目前后端真实生效的发型体系是：

- 男生 23 类
- 女生 33 类
- 共 56 类
- 主分类通过 `categoryKey / categoryLabel` 组织
- 不包含独立刘海分类

如果后面要扩成“主发型 + 刘海标签”模式，需要另做一套数据结构，而不是直接从当前后端 JSON 自动拆出来。
